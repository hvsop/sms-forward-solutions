# 配对、切换与真机验收

## 首次配对

1. 管理员在目标后端创建个人账户，私下提供 HTTPS 服务地址和 `read_token`。每位用户独立账户，不共用令牌。
2. iPhone 设置 → 使用读取令牌连接，填写地址（只有 origin、不含路径）和读取令牌 → 验证并保存。
3. 设置 → 开启／重新注册通知，允许通知与标记。
4. 设置 → 安卓设备与配对 → 添加安卓手机，生成 10 分钟、单次使用的配对码。
5. 安卓填写同一服务器地址，扫描 iPhone 配对码或输入 16 位代码，勾选短信上传说明，点“配对这台手机”。二维码只包含配对码，不包含服务器地址。
6. 授予短信权限，开启转发，配置后台运行。禁用其他重复转发规则。

读取令牌是长期账户凭据，配对码是临时兑换码，两者不能互换。管理员也可使用 `python3 scripts/android-pair.py --invitation 私有邀请.json --endpoint https://sms.example.com` 生成配对码；脚本不打印读取令牌。

## Linux / Cloudflare 切换

1. **旧服务器仍在线时**，先确认安卓“待发送”为 0；否则重试上传并等待。
2. iPhone 使用目标服务地址和该服务的读取令牌连接。
3. 安卓“连接检查与测试 → 切换服务器（先解除配对）”，解除旧配对，再填写目标服务和 iPhone 新生成的配对码。
4. 重新开启转发并按下方验收。

解除配对会清空本地队列。两套服务的账户、令牌和历史相互独立，没有自动迁移。原客户端切换会尝试撤销旧服务器上的注册/配对，所以应先切换再停旧服务。当前一次只保存一套服务器连接，不是多账户并行收件。

Cloudflare 自定义域名与原 workers.dev 若指向同一个 Worker，则是同一个账户空间；旧域名可继续使用，无需仅为缩短地址而强制解除配对。

## 验收

- 将 iPhone 锁屏，安卓发送两条 App 内测试消息，确认收到通知且收件箱可读取。
- 在无其他未读时，角标 2 → 阅读第一条 → 1 → 阅读第二条 → 消失；列表对应行由粗体/小点变为已读。
- 发送真正的 SMS，让安卓锁屏接收；确认最近接收与上传时间更新、待发送为 0、iPhone 收到。App 内测试不能代替短信权限和广播验收。
- 分别重启/重新打开 App，确认连接保存、通知和转发仍正常。
- 可短暂断网验证队列恢复后重试，勿在有待发送条目时解除配对或卸载。
- 如有多用户，用独立虚构内容验证不会跨账户读取或通知。

## 排查

| 现象 | 先检查 |
| --- | --- |
| 系统收到 SMS，App 没有记录 | 短信权限、转发开关、受限设置、强制停止、是否为 RCS |
| 有待发送 | 安卓网络、服务器地址、配对凭据、后端配额，再点重试 |
| 配对失败 | 两端地址相同、配对码未过期且未使用 |
| 令牌错误 | read_token 是否属于当前后端；不要填配对码 |
| 有消息没推送 | iPhone 通知/标记、专注模式、APNs 配置和环境、重新注册通知 |
| 重复提醒 | 关闭其他转发工具；推送可能因重试重复，但入库会去重 |

“清空全部短信”保留连接与配对；“注销账户”会删除账户。不要用注销作为普通清空。
